# 海报自检机制

每天自动检查全站海报，发现错误就重新抓取可信图源并就地替换，替换后还会复检一次。
目标是让「错误海报」在人工发现之前就被机器修掉。

## 一条命令跑完

```bash
npm run poster:qa        # 自检 → 有错就修 → 复检 → 提交推送
```

日常也拆成三步单独用：

```bash
npm run poster:check                 # 只巡检，输出报告；有硬错误时退出码 1
npm run poster:fix                   # 按巡检结果自动纠错并替换
npm run poster:fix -- --dry-run      # 只找候选并校验，不写盘
npm run poster:fix -- 20260701       # 只修指定的日期 ID
```

## 检查哪些问题

`tools/check-posters.mjs` 会对每条 `src/data/gallery.json` 记录做 8 类体检：

| 检查项 | 级别 | 说明 |
| --- | --- | --- |
| `missing_url` / `missing_file` | 错误 | 记录没有地址，或本地 `public/posters/*` 文件不存在 |
| `unreachable` | 错误 | 远程海报下载失败（会先重试 2 次，避免网络抖动误报） |
| `not_image` / `decode_failed` | 错误 | 内容不是图片、或读不出尺寸（例如误存了 HTML 错误页） |
| `too_small_bytes` | 错误 | 文件小于 8KB，基本是缩略图 |
| `low_resolution` | 错误/警告 | 低于 300×400 报错；低于 500 宽提示清晰度偏低 |
| `landscape` | **错误** | **宽高比 h/w < 1.2，说明是横版剧照／Backdrop 被当成竖版海报** |
| `source_is_still` | 错误 | 来源标题自述是「剧照 / backdrop / still」却当成海报用 |
| `no_identity_signal` | **错误** | **海报来源与片名、年份完全对不上 —— 典型的「张冠李戴」错图** |
| `identity_unverified` | **错误** | **只对得上年份、找不到片名证据 —— 疑似配了同年的另一部电影** |
| `duplicate_image` | 错误 | 两部**不同**的电影共用同一张图（同一部电影出现在不同日期不算） |
| `aggregator_host` / `untrusted_host` | 警告 | 图源不是 TMDB / Wikimedia / 官方 CDN |
| `ext_mismatch` / `odd_ratio` | 警告 | 扩展名与真实格式不符、宽高比异常瘦长 |

可信图源白名单在 `tools/lib/poster-audit.mjs` 的 `HOST_TIERS` 里维护
（TMDB、Wikimedia、Amazon/IMDb 官方 CDN），阈值集中在 `THRESHOLDS`。

### 是怎么认出「错图」的

光比对文件名不可靠，所以 `identityScore()` 会同时在三处找线索：
来源标题、来源页地址、图片 URL 本身，再去匹配 **中文片名 / 英文片名 / 可信别名 / 四位年份**。

**关键：只对得上年份不算通过。** 年份是最弱的证据 —— 同一年的其它电影、
榜单页标题（`The Best-Rated Movies from 2013`）、年份区间（`1999-2001`）都会误命中年份。
所以必须出现「片名」证据，否则判为 `identity_unverified`（疑似配错图）。

实测抓到的真实案例：

- 《莫扎特传》挂的是「莫扎伊斯克教堂」照片（Wikimedia 上的 `Mozhaisk11.jpg`），
  片名、年份、图源全无线索 → 命中 `no_identity_signal`；
- 6 部电影的「海报」其实是 16:9 的 TMDB 剧照，来源标题明写「剧照」→ 命中 `landscape` + `source_is_still`；
- 2 部用的是聚合站 236px 缩略图 → 命中 `low_resolution` + `aggregator_host`；
- **《朋友》配的是《创世纪》电视剧海报、《非常警探》配的是《辣手警探2》、
  《蒙太奇》配的是一张 2013 年榜单图、《末代皇帝》配的是《Predator》海报**
  —— 这四张的共同点是「年份对得上、片名对不上」→ 命中 `identity_unverified`。

### 可信片名别名表

站内 `movies.json` 的 `enTitle` 经常是空的或脏数据（如 `2014 · 111 min · Directed by 김성훈`），
拿不到英文名就没法判断「海报标题里那个片名是不是这部电影的」。
所以增加了别名表 `src/data/poster-aliases.json`：

```bash
npm run poster:aliases        # 自动解析（Bing 检索 + 影视站点标题，增量、约 1 分钟）
npm run poster:aliases -- --force   # 全部重跑
```

- `auto`：脚本自动解析，规则是「结果标题形如 `片名 (年份)`、年份与本片一致、来源是影视资料站」；
- `manual`：人工维护，**优先级高于 auto，不会被脚本覆盖**。自动解析不到的条目在这里补。

个别英文名太短（如 `Up`）不足以作为证据，可以写成 `"Up (2009)"` 这种带年份的形式，
归一化后依然能匹配海报标题、又不会误伤。

## 自动纠错怎么做的

`tools/fix-posters.mjs` 按「可信度从高到低」逐层找候选，某一层通过校验就立刻收工：

1. **TMDB 官方 API** —— 配置 `TMDB_API_KEY` 后启用，质量最好、最准确；
2. **Bing 图片搜索** —— 免密钥、稳定，会自动把 TMDB 缩略图地址升级成 `original` 原图；
3. **维基百科** —— 读取条目信息框里的海报原图；
4. **DuckDuckGo 图片** —— 作为补充（有限流风险，只在前几层都没结果时才用）。

每个候选都必须通过 `validateCandidate()` 的严格体检才会被采用：

- 能下载、是有效图片、宽 ≥ 350px、体积 ≥ 15KB；
- 必须是竖版（宽高比 1.2 ~ 2.2）；
- 来源标题／页址必须能对上**片名**（有别名表的电影不允许只靠年份蒙混过关）。

检索时会同时使用「中文名 + 年份」和「可信别名（英文名）+ 年份」两套词，
因为站内中文名常和海报上的名字不一致（例如站内叫《非常警探》，海报上写 `A Hard Day`）。

**校验不通过就宁可不换**，避免「修掉一个错图、又换上一个更错的」。

替换成功后海报会下载到 `public/posters/<id>.<ext>` 改为本地自托管，
并写回 `gallery.json` 的 `imageUrl` / `remoteUrl` / `title` / `hiRes` 字段。

## 产物与日志

| 文件 | 内容 |
| --- | --- |
| `output/poster-audit.json` | 全量巡检结果（机器可读） |
| `output/poster-audit.md` | 巡检报告（人可读，含问题清单表格） |
| `output/poster-audit-history.jsonl` | 每次巡检追加一行，用于看趋势 |
| `output/poster-fix-log.json` | 本次纠错的替换明细与复检结果 |

巡检报告会随提交一起入库，用来回溯「哪张图在什么时候被谁换过」。

## 每天怎么自动跑

两条链路，互为补充：

1. **有新内容时**：`tools/daily-sync.sh` 在抓完新海报后，立刻调用
   `tools/poster-qa.sh --no-commit` 做一次自检，错误海报不会入库上线；
2. **没有新内容时**：`launchd` 定时任务每天 03:30 全站巡检一次
   （机器休眠错过时间点，唤醒后 launchd 会补跑）。

两者共用 `/tmp/classicmovie-posterqa.lock` 防并发，重复触发会自动跳过。

### 安装 / 卸载定时任务

```bash
# 安装（已装可跳过）
cp deploy/com.classicmovie.poster-qa.plist ~/Library/LaunchAgents/
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.classicmovie.poster-qa.plist

# 查看
launchctl list | grep classicmovie
tail -f /tmp/classicmovie-posterqa.log

# 卸载
launchctl bootout gui/$(id -u)/com.classicmovie.poster-qa
rm ~/Library/LaunchAgents/com.classicmovie.poster-qa.plist
```

## 可选：打开 TMDB 官方 API（推荐）

不配也能跑，但配上后优先走 TMDB API，准确率和分辨率都是最好的：

```bash
export TMDB_API_KEY=你的_key        # 或 TMDB_READ_TOKEN（v4 Bearer Token）
```

在 <https://www.themoviedb.org/settings/api> 免费申请。配置到 `tools/poster-qa.sh`
的调用环境（例如 `supabase/.env.local` 里加一行，脚本会自动加载）。

## 可选：把剩余远程海报也改成本地自托管

目前仍有少量记录直接引用远程地址。执行一次下面命令可以全部下载到本地，
此后巡检不再需要联网，速度更快、也不受第三方图床失效影响：

```bash
node tools/fix-posters.mjs --self-host-all
```

## 调整判定标准

所有阈值都集中在 `tools/lib/poster-audit.mjs`：

```js
export const THRESHOLDS = {
  minPortraitRatio: 1.2,   // 低于此比例视为横版剧照
  maxPortraitRatio: 2.2,
  minWidth: 300,
  minHeight: 400,
  warnWidth: 500,
  minBytes: 8 * 1024,
};
```

候选准入标准在 `tools/lib/poster-repair.mjs` 的 `CANDIDATE_RULES`。
想放宽或收紧严格程度，改这两处即可，不需要动流程代码。
